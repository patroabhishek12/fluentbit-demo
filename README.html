Fluent Bit → Splunk + Prometheus + Grafana

One docker compose up demo: Fluent Bit tails app logs into Splunk and scrapes app metrics for Prometheus, which Grafana charts.

Architecture

orders ──┐  JSON logs  (shared volume /logs)           ┌─► Splunk HEC :8088  ─► Splunk Web :8000
         ├──────────────────────────► Fluent Bit ──────┤
payments ┘  /metrics (HTTP :8000)       (tail +         └─► prometheus_exporter :2021
                                      prometheus_scrape)            ▲
                                                          Prometheus :9090 scrapes
                                                                    │
                                                              Grafana :3000

Fluent Bit is the only collector. Apps know nothing about Splunk or Prometheus.

Run it

docker compose up -d --build
docker compose ps          # splunk takes 2-4 min to become healthy; fluent-bit waits for it
docker compose logs -f fluent-bit

What to show in the demo

1. Logs in Splunk

Search & Reporting, then:

index=main sourcetype="app:json" | stats count by app, level
index=main level=ERROR | timechart span=10s count by app
index=main app=payments | stats avg(duration_ms) p95(duration_ms) by path

2. Metrics in Prometheus / Grafana

sum by (app)(rate(app_requests_total[1m]))
histogram_quantile(0.95, sum by (le,app)(rate(app_request_duration_seconds_bucket[1m])))
sum by (name)(rate(fluentbit_output_proc_records_total[1m]))   # Fluent Bit itself

3. Resilience (good live moment)

docker compose stop splunk      # Fluent Bit logs retries; metrics keep flowing
docker compose start splunk     # buffered logs are delivered, nothing lost (Retry_Limit False)

Watch fluentbit_output_retries_total climb in Grafana/Prometheus while Splunk is down. For real durability add storage.type filesystem to the tail input.

How the pieces work

PieceConfigNotes
Log inputtail on /logs/*.logApps write JSON lines to a shared volume. For real containers, tail /var/lib/docker/containers/*/*-json.log with the docker parser, or use the forward input with Docker's fluentd log driver.
Metrics inputprometheus_scrape ×2, fluentbit_metricsFluent Bit pulls /metrics from each app every 5s. Fluent Bit's own metrics ride the same pipeline.
Logs outputsplunk (HEC)Token set via SPLUNK_HEC_TOKEN; TLS.Verify Off because Splunk uses a self-signed cert.
Metrics outputprometheus_exporter on :2021Prometheus scrapes Fluent Bit, with honor_labels: true to keep the app label.

Alternative: push metrics with remote write

Instead of the exporter, push straight to Prometheus. Start Prometheus with --web.enable-remote-write-receiver and replace the metrics output:

[OUTPUT]
    Name   prometheus_remote_write
    Match  metrics.*
    Host   prometheus
    Port   9090
    Uri    /api/v1/write

Troubleshooting

SymptomFix
Splunk never healthy / slowImage is amd64 only; on Apple Silicon it runs emulated and can take 5+ min. Needs ~4 GB RAM.
No logs in Splunkdocker compose logs fluent-bit: look for HTTP 400/403 (token mismatch) or connection refused. Check index=main and time range "Last 15 minutes".
Prometheus target downOpen localhost:2021/metrics; empty means the scrape inputs can't reach orders:8000/payments:8000.
Splunk license promptSplunk's env var for accepting terms changes between releases; see the image's README on Docker Hub if SPLUNK_GENERAL_TERMS is rejected.
